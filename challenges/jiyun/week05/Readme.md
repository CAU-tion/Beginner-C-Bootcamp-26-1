## Challenge1. 메모리 레이아웃 이해하기

### 실습 내용  
각 메모리 영역(Text, Data, BSS, Heap, Stack)에 데이터가 어떻게 저장되는지 확인하기 위해  
각 영역에 해당하는 변수를 포함하는 코드를 직접 작성하였다.  

프로그램은 다음과 같은 변수들로 구성하였다.  

- 초기화된 전역변수 → Data 영역  
- 초기화되지 않은 전역변수 → BSS 영역  
- 지역변수 → Stack 영역  
- `malloc()`으로 할당한 변수 → Heap 영역  
- 문자열 리터럴 → Text(Code) 영역  

코드를 `gcc -g -O0` 옵션으로 컴파일한 후,  
`printf`를 이용해 각 변수의 주소를 출력하였다.  

이후 gdb를 이용하여 프로그램을 실행하고,  
`info proc mappings` 명령어를 통해 각 주소가 실제로 어느 메모리 영역에 속하는지 확인하였다.  

---

### 핵심 개념  

프로세스의 메모리 구조는 여러 영역으로 나뉘어 관리된다.  

- Text 영역 : 프로그램 코드 및 문자열 리터럴 저장  
- Data 영역 : 초기화된 전역변수 저장  
- BSS 영역 : 초기화되지 않은 전역변수 저장  
- Heap 영역 : 동적 할당된 메모리 (`malloc`)  
- Stack 영역 : 함수 호출 시 생성되는 지역변수 및 스택 프레임  

각 변수의 주소를 확인한 뒤, 해당 주소가 `info proc mappings`에서 나타나는 범위에 포함되는지를 비교하여  
실제 메모리 영역과 일치하는지 검증하였다.  

---

### 실습 결과  

- 초기화된 전역변수와 초기화되지 않은 전역변수는 인접한 주소에 위치하며,  
  Data/BSS 영역에 저장되는 것을 확인하였다.  

- 지역변수는 높은 주소 영역에 위치하며 Stack 영역에 저장되는 것을 확인하였다.  

- `malloc()`으로 할당한 변수는 Heap 영역에 위치하였다.  

- 문자열 리터럴은 읽기 전용 영역(Text 또는 rodata)에 위치하는 것을 확인하였다.

## Challenge2. 버퍼 오버플로우 실험

### 실습 내용  

버퍼 오버플로우 취약점을 확인하기 위해 `gets()` 함수를 사용하는 취약한 코드를 작성하였다.  

해당 코드를 `gcc -g -O0 -fno-stack-protector` 옵션으로 컴파일하여  
스택 보호 기법을 비활성화한 상태에서 실험을 진행하였다.  

정상 입력과 16바이트를 초과하는 입력을 각각 실행하여 동작 차이를 비교하였다.  

또한 gdb를 이용하여 `vuln()` 함수 실행 시 스택 구조를 확인하고,  
`print &buf`, `x/32gx $rsp` 명령어를 통해 버퍼와 스택의 상태를 관찰하였다.  

---

### 핵심 개념  

버퍼 오버플로우(Buffer Overflow)는 버퍼의 크기를 초과하는 데이터를 입력할 경우  
인접한 메모리 영역까지 덮어쓰게 되는 취약점이다.  

스택 구조는 일반적으로 다음과 같이 구성된다.  

- 지역 변수 (buf)  
- saved rbp  
- return address  

버퍼의 크기를 초과하는 입력이 들어오면  
지역 변수를 넘어 saved rbp 및 return address까지 덮어쓸 수 있다.  

---

### 실습 결과  

- 정상 입력의 경우 프로그램이 정상적으로 종료되었다.  

- 16바이트를 초과하는 문자열을 입력한 경우,  
  프로그램이 비정상 종료되거나 segmentation fault가 발생하였다.  

- gdb에서 긴 입력을 넣은 후 스택을 확인한 결과,  
  `0x4141414141414141` 값이 반복적으로 나타나는 것을 확인하였다.  

- 이는 입력한 문자열(`AAAA...`)이 버퍼를 넘어 스택 영역을 덮어쓴 것을 의미한다.  

---

### 원리  

버퍼 오버플로우는 입력 데이터가 버퍼 크기를 초과할 때 발생한다.  

1. `gets()` 함수는 입력 길이에 대한 제한이 없음  
2. buf[16]을 초과하는 데이터 입력  
3. 인접한 메모리 영역 덮어쓰기 발생  
4. 스택 구조 손상  
5. 프로그램 비정상 종료 또는 제어 흐름 변경 가능  

---

### 추가 조사  

`gets()` 외에도 다음과 같은 함수들은 버퍼 오버플로우에 취약하다.  

- `strcpy()`  
- `strcat()`  
- `sprintf()`  
- `scanf("%s")`  

이러한 함수들은 입력 길이를 제한하지 않기 때문에  
버퍼 크기를 초과하는 데이터를 처리할 경우 취약점이 발생할 수 있다.  

이를 방지하기 위해 다음과 같은 안전한 함수 사용이 권장된다.  

- `fgets()`  
- `strncpy()`  
- `snprintf()`
