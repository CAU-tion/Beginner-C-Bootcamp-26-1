## Challenge1. malloc / free 기초 실습

### 실습 내용

`malloc()`을 사용하여 정수 1개와 `int`형 배열 5개를 Heap 영역에 동적으로 할당하였다.  
할당된 메모리에 값을 저장하고 출력한 뒤, 주소값을 확인하여 동적 할당된 메모리가 Heap 영역에 위치하는지 확인하였다.  
사용이 끝난 메모리는 `free()`를 사용하여 해제하였다.

---

### 핵심 개념

`malloc()`은 프로그램 실행 중 필요한 메모리를 Heap 영역에 동적으로 할당하는 함수이다.  
할당에 성공하면 할당된 메모리의 시작 주소를 반환하고, 실패하면 `NULL`을 반환한다.

따라서 `malloc()` 사용 후에는 반환값이 `NULL`인지 확인해야 한다.  
만약 `NULL` 체크 없이 메모리에 접근하면 프로그램 오류가 발생할 수 있다.

`free()`는 `malloc()`으로 할당한 메모리를 해제하는 함수이다.  
동적으로 할당한 메모리를 사용한 뒤 `free()`하지 않으면, 사용하지 않는 메모리가 계속 남아 있게 된다.  
이러한 문제를 Memory Leak이라고 한다.

Memory Leak이 반복되면 프로그램의 메모리 사용량이 증가하고,  
장시간 실행되는 프로그램에서는 성능 저하나 비정상 종료로 이어질 수 있다.

---

### 실행 결과 및 정리

정수 1개와 `int`형 배열 5개가 정상적으로 동적 할당되었고,  
할당된 공간에 저장한 값들이 정상적으로 출력되었다.

`gdb`에서 `info proc mappings` 명령어를 사용하여 Heap 영역의 주소 범위를 확인하였다.

```text
0x555555559000 ~ 0x55555557a000 [heap]
```

또한 `print num`, `print arr` 명령어로 `malloc()`을 통해 할당된 주소를 확인하였다.

```text
num = 0x5555555592a0
arr = 0x5555555592c0
```

두 주소 모두 `[heap]` 영역 범위 안에 있으므로,  
`malloc()`으로 할당된 메모리가 Heap 영역에 저장됨을 확인할 수 있었다.

## Challenge2. Dangling Pointer 실험

### 실습 내용

`malloc()`으로 메모리를 할당한 뒤 값을 저장하고, `free()`로 메모리를 해제하였다.  
이후 해제된 포인터를 그대로 사용하여 값을 읽거나 쓰는 코드를 실행하였다.

또한 `gdb`를 사용하여 `free()` 실행 전과 실행 후의 포인터 주소 및 메모리 값을 비교하였다.

---

### 핵심 개념

Dangling Pointer는 이미 해제된 메모리 주소를 계속 가리키고 있는 포인터를 의미한다.

`free()`를 호출하면 해당 메모리는 더 이상 사용하면 안 되는 상태가 된다.  
하지만 포인터 변수에 저장된 주소값이 자동으로 사라지는 것은 아니다.

따라서 `free()` 이후 같은 포인터를 사용하면 이미 해제된 메모리에 접근하게 된다.  
이는 정의되지 않은 동작이기 때문에 실행 결과를 예측할 수 없다.

환경에 따라 다음과 같은 결과가 나타날 수 있다.

- 정상 실행되는 것처럼 보임
- 이상한 값이 출력됨
- 프로그램이 크래시됨

이러한 문제는 Use After Free, 즉 UAF 취약점과 연결된다.  
UAF는 해제된 메모리를 다시 사용하는 취약점으로,  
공격자가 해제된 메모리 공간을 조작할 경우 프로그램이 의도하지 않은 동작을 하게 만들 수 있다.

Dangling Pointer를 예방하기 위해서는 `free()` 이후 포인터를 `NULL`로 초기화하는 것이 좋다.

```c
free(p);
p = NULL;
```

---

### 실행 결과 및 정리

`gdb`에서 `free(p)` 실행 전후의 상태를 비교하였다.

`free()` 실행 전 `p`의 주소는 다음과 같았다.

```text
p = 0x5555555592a0
```

해당 주소의 메모리 값은 다음과 같았다.

```text
0x5555555592a0: 0x000004d2  0x00000000  0x00000000  0x00000000
```

`0x000004d2`는 10진수로 `1234`이므로,  
`malloc()`으로 할당한 공간에 저장한 값이 정상적으로 확인되었다.

`free(p)` 실행 후에도 `p`의 주소는 동일하였다.

```text
p = 0x5555555592a0
```

하지만 해당 주소의 메모리 값은 다음과 같이 변경되었다.

```text
0x5555555592a0: 0x55555559  0x00000005  0xb885e4fd  0x0d15c02a
```

이를 통해 `free()`를 호출해도 포인터 변수의 주소값은 그대로 남아 있지만,  
해당 메모리는 이미 해제된 상태가 되어 더 이상 안전하게 사용할 수 없음을 확인하였다.

즉, `free()` 이후에도 기존 주소를 가리키는 `p`는 Dangling Pointer가 된다.

## Challenge3. Double Free Bug 실험

### 실습 내용

`malloc()`으로 메모리를 할당한 뒤, 같은 포인터에 대해 `free()`를 두 번 호출하였다.  
이를 통해 Double Free가 발생하는 상황을 확인하였다.

또한 `gdb`를 사용하여 첫 번째 `free()` 실행 전과 두 번째 `free()` 실행 전의 메모리 상태를 비교하였다.

---

### 핵심 개념

Double Free는 이미 해제된 메모리를 다시 해제하려고 할 때 발생하는 버그이다.

첫 번째 `free()`를 호출하면 해당 메모리는 이미 해제된 상태가 된다.  
그런데 같은 포인터에 대해 다시 `free()`를 호출하면, 이미 해제된 메모리를 다시 해제하려는 동작이 된다.

Heap은 내부적으로 어떤 메모리 블록이 사용 중인지, 어떤 메모리 블록이 해제되었는지를 관리한다.  
이때 Heap 관리를 위해 사용되는 내부 정보를 Heap Metadata라고 한다.

Double Free가 발생하면 Heap Metadata가 손상될 수 있다.  
공격자가 이를 악용하면 Heap 관리 구조를 조작할 수 있으며, 이는 Heap Exploitation과 연결된다.

현대 시스템에서는 Double Free를 감지하면  
Heap 구조 손상을 막기 위해 프로그램을 강제로 종료시키는 경우가 많다.

Double Free를 예방하기 위해서는 `free()` 이후 포인터를 `NULL`로 초기화하고,  
같은 포인터를 중복으로 해제하지 않도록 해야 한다.

```c
free(p);
p = NULL;
```

---

### 실행 결과 및 정리

프로그램 실행 결과, 첫 번째 `free(p)` 이후 두 번째 `free(p)`에서 다음과 같은 오류가 발생하였다.

```text
free(): double free detected in tcache 2
Aborted (core dumped)
```

이는 이미 해제된 메모리를 다시 해제하려고 했기 때문에 발생한 오류이다.

`gdb`에서 첫 번째 `free()` 실행 전 `p`의 주소는 다음과 같았다.

```text
p = 0x5555555592a0
```

해당 주소의 메모리 값은 다음과 같았다.

```text
0x5555555592a0: 0x00000309  0x00000000  0x00000000  0x00000000
```

`0x00000309`는 10진수로 `777`이므로,  
할당된 메모리에 저장한 값이 정상적으로 확인되었다.

첫 번째 `free()` 실행 후, 두 번째 `free()` 직전에도 `p`의 주소는 동일하였다.

```text
p = 0x5555555592a0
```

하지만 해당 주소의 메모리 값은 다음과 같이 변경되었다.

```text
0x5555555592a0: 0x55555559  0x00000005  0x1be3c576  0xb1a96d64
```

즉, 첫 번째 `free()` 이후에도 포인터 변수 `p`에는 기존 주소값이 남아 있지만,  
해당 메모리는 이미 해제된 상태가 되었다.

이 상태에서 두 번째 `free(p)`를 실행하자 다음과 같은 메시지가 출력되었다.

```text
free(): double free detected in tcache 2

Program received signal SIGABRT, Aborted.
```

이를 통해 동일한 메모리를 두 번 해제하면 Double Free가 발생하며,  
시스템이 이를 감지하고 프로그램을 강제로 종료한다는 것을 확인하였다.

---

### Double Free와 보안 취약점

Double Free는 단순히 프로그램이 두 번 `free()`를 호출해서 종료되는 오류로 끝나는 것이 아니라,  
Heap 관리 구조를 손상시켜 실제 보안 취약점으로 이어질 수 있다.

Heap은 동적 할당된 메모리 블록들을 관리하기 위해 내부적으로 메타데이터를 사용한다.  
이 메타데이터에는 해당 메모리 블록의 크기, 사용 여부, 다음 빈 공간을 가리키는 정보 등이 포함될 수 있다.

`free()`가 호출되면 해당 메모리 블록은 사용 가능한 공간으로 표시되고,  
메모리 할당자가 관리하는 free list 또는 tcache와 같은 구조에 등록된다.

그런데 같은 포인터에 대해 `free()`를 두 번 호출하면,  
이미 해제된 메모리 블록이 다시 해제 목록에 들어가게 된다.  
이로 인해 Heap 관리 구조가 꼬이거나, 같은 메모리 블록이 중복으로 재사용될 수 있다.

공격자는 이 상황을 악용하여 해제된 Heap 영역의 메타데이터나 포인터 값을 조작할 수 있다.  
그 결과 이후 `malloc()`이 호출될 때 공격자가 원하는 주소가 할당되도록 유도하거나,  
특정 주소에 값을 쓰게 만드는 방식으로 프로그램의 흐름을 조작할 수 있다.

이처럼 Heap 영역의 관리 구조를 조작하여 공격하는 기법을 Heap Exploitation이라고 한다.

즉, Double Free는 다음과 같은 흐름으로 보안 취약점과 연결될 수 있다.

1. 프로그램이 같은 메모리를 두 번 `free()`함
2. Heap 관리 구조에 같은 메모리 블록이 중복 등록됨
3. 공격자가 해제된 메모리 영역이나 Heap Metadata를 조작함
4. 이후 `malloc()` 호출 시 조작된 주소가 반환되도록 유도함
5. 공격자가 원하는 메모리 영역에 값을 쓰거나 프로그램 흐름을 변경할 수 있음

현대 시스템에서는 이러한 공격을 막기 위해 Double Free를 감지하면  
`free(): double free detected in tcache`와 같은 메시지를 출력하고 프로그램을 종료시키는 경우가 많다.

## 최종 정리

이번 실습에서는 C언어의 동적 할당과 Heap 영역에서 발생할 수 있는 대표적인 메모리 문제를 확인하였다.

`malloc()`을 사용하면 프로그램 실행 중 필요한 메모리를 Heap 영역에 동적으로 할당할 수 있다.  
하지만 사용이 끝난 메모리를 `free()`하지 않으면 Memory Leak이 발생할 수 있다.

또한 `free()` 이후에도 포인터 변수에는 기존 주소값이 남아 있기 때문에,  
해제된 메모리를 다시 사용하면 Dangling Pointer 문제가 발생한다.  
이는 Use After Free 취약점으로 이어질 수 있다.

Double Free는 같은 메모리를 두 번 해제하는 버그이다.  
이는 Heap Metadata 손상과 연결될 수 있으며, Heap Exploitation의 원리가 될 수 있다.

따라서 동적 할당을 사용할 때는 다음 사항을 주의해야 한다.

- `malloc()` 후 `NULL` 체크를 수행한다.
- 사용이 끝난 메모리는 반드시 `free()` 한다.
- `free()` 이후 포인터를 `NULL`로 초기화한다.
- 해제된 메모리에 다시 접근하지 않는다.
- 같은 포인터를 두 번 `free()`하지 않는다.
