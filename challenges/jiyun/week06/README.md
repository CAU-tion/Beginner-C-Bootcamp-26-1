## Challenge1. 포인터 기초 실습

### 실습 내용  

포인터의 기본 개념을 직접 코드로 확인하기 위해  
`int` 변수를 선언하고, 해당 변수를 가리키는 포인터 변수를 선언하였다.  

프로그램은 다음과 같은 내용으로 구성하였다.  

- `int` 변수 선언  
- 해당 변수를 가리키는 포인터 변수 선언  
- `&` 연산자를 사용하여 변수의 주소 출력  
- `*` 연산자를 사용하여 포인터가 가리키는 값 출력  
- 포인터를 통해 원본 변수의 값 변경  
- `sizeof()`를 이용하여 포인터 변수의 크기 출력  
- 포인터 변수 자체의 주소 출력  

코드를 컴파일하고 실행하여  
포인터가 변수의 주소를 저장하고, 해당 주소를 통해 원본 변수의 값에 접근하거나 변경할 수 있음을 확인하였다.  

---

### 핵심 개념  

포인터는 다른 변수의 메모리 주소를 저장하는 변수이다.  

일반 변수는 값을 저장하지만, 포인터 변수는 값이 저장된 위치인 주소를 저장한다.  

포인터에서 사용하는 주요 연산자는 다음과 같다.  

- `&` 연산자 : 변수의 주소를 구할 때 사용  
- `*` 연산자 : 포인터가 가리키는 주소에 저장된 값에 접근할 때 사용  

따라서 `&num`은 `num`의 주소를 의미하고,  
`*ptr`은 `ptr`이 가리키는 주소에 저장된 값, 즉 `num`의 값을 의미한다.  

또한 `*ptr = 20;`과 같이 작성하면  
포인터를 통해 원본 변수인 `num`의 값을 직접 변경할 수 있다.  

포인터 변수의 크기는 포인터가 가리키는 자료형의 크기와 관계없이  
주소를 저장하기 위한 크기로 결정된다.  

64비트 환경에서는 주소를 표현하기 위해 8바이트가 필요하므로,  
포인터 변수의 크기는 일반적으로 8바이트로 출력된다.  

---

### 실습 결과  

- `&num`과 `ptr`이 같은 주소를 출력하는 것을 확인하였다.  

- `*ptr`을 사용하여 포인터가 가리키는 변수의 값을 출력할 수 있었다.  

- `*ptr = 20;`을 수행한 후 원본 변수 `num`의 값도 함께 변경되는 것을 확인하였다.  

- `sizeof(ptr)`을 통해 포인터 변수의 크기를 확인한 결과,  
  64비트 환경에서 8바이트로 출력되었다.  

- 포인터 변수도 하나의 변수이므로  
  `&ptr`을 통해 포인터 변수 자체의 주소를 확인할 수 있었다.

## Challenge2. 포인터 연산 실습

### 실습 내용  

배열과 포인터의 관계를 직접 코드로 확인하기 위해  
`int` 배열을 선언하고, 배열을 가리키는 포인터 변수를 선언하였다.  

프로그램은 다음과 같은 내용으로 구성하였다.  

- `int` 배열 선언  
- 배열의 첫 번째 원소를 가리키는 포인터 변수 선언  
- `arr[i]` 방식으로 배열 원소 출력  
- `*(ptr + i)` 방식으로 배열 원소 출력  
- 두 방식이 동일한 결과를 출력하는지 확인  
- `ptr + 1`, `ptr + 2`를 출력하여 포인터 주소 이동 확인  
- `ptr++`, `ptr--`을 사용하여 포인터 증감 연산 확인  

코드를 실행한 후 배열 인덱스 방식과 포인터 연산 방식이  
같은 배열 원소에 접근한다는 것을 확인하였다.  

또한 포인터 연산 시 주소가 단순히 1씩 증가하는 것이 아니라,  
포인터가 가리키는 자료형의 크기만큼 이동한다는 것을 확인하였다.  

---

### 핵심 개념  

배열 이름은 대부분의 상황에서 배열의 첫 번째 원소 주소처럼 사용된다.  

`int arr[5] = {10, 20, 30, 40, 50};`  
`int *ptr = arr;`  

위 코드에서 `arr`은 `&arr[0]`과 같은 의미로 사용될 수 있다.  
따라서 `ptr`은 배열의 첫 번째 원소인 `arr[0]`의 주소를 저장한다.  

배열 원소에 접근하는 방식은 다음 두 가지가 있다.  

- `arr[i]`
- `*(ptr + i)`

`arr[i]`는 배열의 인덱스를 이용해 원소에 접근하는 방식이고,  
`*(ptr + i)`는 포인터 연산을 이용해 같은 원소에 접근하는 방식이다.  

포인터 연산에서 `ptr + i`는 주소에 단순히 `i`를 더하는 것이 아니라,  
포인터가 가리키는 자료형의 크기만큼 이동한 주소를 의미한다.  

예를 들어 `int`형 포인터에서 `ptr + 1`은 주소가 1만큼 증가하는 것이 아니라,  
`int`의 크기인 4바이트만큼 이동한다.  

따라서 `ptr++`을 수행하면 다음 배열 원소로 이동하고,  
`ptr--`을 수행하면 이전 배열 원소로 다시 이동한다.  

---

### 실습 결과  

- `arr[i]` 방식과 `*(ptr + i)` 방식이 동일한 값을 출력하는 것을 확인하였다.  

- `&arr[i]`와 `ptr + i`가 같은 주소를 가리키는 것을 확인하였다.  

- `ptr + 1`, `ptr + 2`를 출력한 결과,  
  주소가 `int` 자료형의 크기만큼 이동하는 것을 확인하였다.  

- `ptr++`을 수행하면 포인터가 다음 배열 원소를 가리키고,  
  `ptr--`을 수행하면 다시 이전 배열 원소를 가리키는 것을 확인하였다.  

- 배열 이름 `arr`은 배열의 첫 번째 원소 주소처럼 사용되기 때문에  
  포인터를 이용하여 배열 원소에 접근할 수 있음을 확인하였다.  

- 즉, 배열 이름 `arr`은 식에서 사용될 때 배열의 첫 번째 원소 주소인 `&arr[0]`로 변환되기 때문에,  
  `int *ptr = arr;`로 선언한 포인터 `ptr`과 비슷하게 배열 원소에 접근할 수 있다.  
  따라서 `arr[i]`는 내부적으로 `*(arr + i)`와 같은 의미로 해석될 수 있고,  
  `ptr[i]` 또는 `*(ptr + i)`와 같은 방식으로도 동일한 원소에 접근할 수 있다.

## Challenge3. call by value vs call by reference 비교

### 실습 내용  

함수 호출 시 값을 전달하는 방식의 차이를 확인하기 위해  
두 정수를 교환하는 `swap` 함수를 두 가지 방식으로 작성하였다.  

프로그램은 다음과 같은 함수로 구성하였다.  

- `swap_by_value(int a, int b)`  
- `swap_by_reference(int *a, int *b)`  

`swap_by_value()` 함수는 정수 값을 인자로 받아  
함수 내부에서 두 값을 교환하도록 작성하였다.  

`swap_by_reference()` 함수는 정수 변수의 주소를 인자로 받아  
포인터를 통해 원본 변수의 값을 직접 교환하도록 작성하였다.  

각 함수 호출 전후로 원본 변수의 값을 출력하여  
두 방식의 차이를 비교하였다.  

---

### 핵심 개념  

`call by value`는 함수에 값을 전달할 때  
원본 값이 아니라 복사된 값을 전달하는 방식이다.  

`void swap_by_value(int a, int b)`  

위 함수에서 `a`와 `b`는 원본 변수의 값이 복사된 지역 변수이다.  
따라서 함수 내부에서 `a`와 `b`의 값을 바꾸더라도  
원본 변수의 값은 변경되지 않는다.  

반면 `call by reference`는 변수의 주소를 전달하여  
함수 내부에서 원본 변수에 접근할 수 있도록 하는 방식이다.  

`void swap_by_reference(int *a, int *b)`  

위 함수에서 `a`와 `b`는 정수형 포인터이다.  
즉, 원본 변수의 주소를 저장하고 있다.  

따라서 `*a`, `*b`를 사용하면  
해당 주소에 저장된 원본 변수의 값에 직접 접근할 수 있다.  

C언어는 기본적으로 함수 인자를 값으로 전달하지만,  
주소값을 인자로 전달하면 포인터를 통해 원본 값에 접근할 수 있으므로  
call by reference처럼 동작하게 만들 수 있다.  

---

### 실습 결과  

- `swap_by_value()` 함수 내부에서는 두 값이 서로 바뀌는 것을 확인하였다.  

- 하지만 `swap_by_value()` 함수 호출 후  
  원본 변수의 값은 변경되지 않았다.  

- 이는 함수에 전달된 값이 원본이 아니라 복사본이기 때문이다.  

- `swap_by_reference()` 함수 호출 후에는  
  원본 변수의 값이 실제로 서로 바뀌는 것을 확인하였다.  

- 이는 변수의 주소를 전달하고,  
  포인터를 통해 원본 변수에 직접 접근했기 때문이다.  

---

### 원리  

두 방식의 차이는 함수에 전달되는 값이  
원본 데이터의 복사본인지, 원본 데이터의 주소인지에 따라 발생한다.  

call by value 방식은 다음과 같이 동작한다.  

1. `swap_by_value(x, y)` 호출  
2. `x`, `y`의 값이 함수의 매개변수 `a`, `b`에 복사됨  
3. 함수 내부에서 `a`, `b`를 교환  
4. 원본 변수 `x`, `y`는 변경되지 않음  

반면 call by reference 방식은 다음과 같이 동작한다.  

1. `swap_by_reference(&x, &y)` 호출  
2. `x`, `y`의 주소가 함수의 매개변수 `a`, `b`에 전달됨  
3. 함수 내부에서 `*a`, `*b`를 사용하여 원본 값에 접근  
4. 원본 변수 `x`, `y`의 값이 실제로 변경됨  

---

### 추가 정리  

`call by value`는 원본 값을 변경할 필요가 없을 때 사용한다.  
함수 내부에서 값을 수정해도 원본 데이터가 보호된다는 장점이 있다.  

`call by reference` 방식은 함수 내부에서 원본 값을 변경해야 할 때 사용한다.  
예를 들어 두 변수의 값을 교환하거나, 함수 실행 결과를 여러 개 반환해야 하는 경우에 사용할 수 있다.  

포인터를 사용할 때는 원본 데이터에 직접 접근할 수 있기 때문에 편리하지만,  
잘못된 주소를 참조하거나 초기화되지 않은 포인터를 사용할 경우  
프로그램 오류가 발생할 수 있으므로 주의해야 한다.
