## Challenge1. 단순 연결리스트 구현

### 실습 내용

포인터와 동적 할당을 활용하여 단방향 연결리스트를 구현하였다.
노드 5개를 추가한 뒤 전체 리스트를 출력하고, 중간 노드 1개를 삭제한 뒤 다시 출력하였다.
또한 `gdb`를 사용하여 노드가 Heap 영역에 할당되는지 확인하고, 각 노드의 주소와 `next` 포인터가 가리키는 주소를 확인하였다.

---

### 핵심 개념

연결리스트는 여러 개의 노드가 포인터로 연결된 자료구조이다.
배열은 메모리상에 연속적으로 저장되지만, 연결리스트의 노드는 Heap 영역에 각각 동적으로 할당될 수 있다.
각 노드는 데이터와 다음 노드의 주소를 저장하는 포인터를 가진다.

단방향 연결리스트는 한 방향으로만 이동할 수 있는 연결리스트이다.
각 노드는 다음 노드를 가리키는 `next` 포인터만 가지고 있으며, 마지막 노드의 `next`는 `NULL`이다.

이번 실습에서 사용한 주요 함수의 기능은 다음과 같다.

* `create_node()`
  새 노드를 동적으로 생성하고, 데이터 값을 저장한 뒤 `next`를 `NULL`로 초기화한다.

* `append()`
  연결리스트의 마지막에 새 노드를 추가한다.
  리스트가 비어 있으면 새 노드가 첫 번째 노드가 되고, 이미 노드가 있으면 마지막 노드의 `next`가 새 노드를 가리키도록 한다.

* `delete_node()`
  특정 값을 가진 노드를 찾아 삭제한다.
  삭제할 노드의 이전 노드가 삭제할 노드의 다음 노드를 가리키도록 연결을 바꾼 뒤, 삭제 대상 노드는 `free()`로 해제한다.

* `print_list()`
  첫 번째 노드부터 마지막 노드까지 이동하면서 전체 리스트를 출력한다.

* `free_list()`
  프로그램 종료 전 연결리스트에 남아 있는 모든 노드를 순서대로 해제한다.

---

### 실행 결과 및 정리

10, 20, 30, 40, 50 총 5개의 노드를 추가한 뒤 전체 리스트를 출력하였다.

```text
10 -> 20 -> 30 -> 40 -> 50 -> NULL
```

이후 중간 노드인 30을 삭제한 뒤 다시 출력하였다.

```text
10 -> 20 -> 40 -> 50 -> NULL
```

이를 통해 중간 노드를 삭제하면 이전 노드의 `next`가 삭제된 노드의 다음 노드를 가리키도록 변경된다는 것을 확인하였다.

`gdb`에서는 `info proc mappings` 명령어로 Heap 영역을 확인하고, `print new_node` 명령어로 새로 생성된 노드의 주소를 확인하였다.
확인한 노드 주소가 `[heap]` 영역 범위 안에 있었으므로, `malloc()`으로 생성된 노드가 Heap 영역에 할당되었음을 확인하였다.

또한 `print head`, `print *head`, `print *(head->next)` 등의 명령어를 사용하여 각 노드의 `next` 포인터가 다음 노드의 주소를 가리키는 것을 확인하였다.
마지막 노드의 `next`는 `NULL`이었다.

## Challenge2. 스택 구현

### 실습 내용

연결리스트를 기반으로 스택 자료구조를 구현하였다.
`push(1)`, `push(2)`, `push(3)`을 실행한 뒤 전체 스택을 출력하고, `pop()`을 두 번 실행한 뒤 다시 출력하였다.
마지막으로 빈 스택에서 `pop()`을 실행했을 때 예외 처리가 정상적으로 되는지 확인하였다.

---

### 핵심 개념

스택은 LIFO 구조를 가지는 자료구조이다.
LIFO는 Last In First Out의 약자로, 마지막에 들어온 데이터가 가장 먼저 나가는 방식을 의미한다.

예를 들어 1, 2, 3 순서로 데이터를 넣으면 스택의 맨 위에는 3이 위치한다.
따라서 `pop()`을 하면 3이 가장 먼저 제거되고, 그 다음 2, 그 다음 1이 제거된다.

연결리스트 기반 스택에서는 `top` 포인터가 스택의 가장 위에 있는 노드를 가리킨다.
새로운 데이터를 추가할 때는 새 노드를 `top` 위치에 추가하고, 데이터를 제거할 때는 현재 `top` 노드를 제거한다.

이번 실습에서 사용한 주요 함수의 기능은 다음과 같다.

* `push()`
  스택의 맨 위에 새 데이터를 추가한다.
  새 노드의 `next`가 기존 `top`을 가리키게 한 뒤, `top`을 새 노드로 변경한다.

* `pop()`
  스택의 맨 위에 있는 데이터를 제거한다.
  현재 `top` 노드를 제거하고, `top`을 다음 노드로 이동시킨다.
  빈 스택에서 호출될 경우 오류가 발생하지 않도록 예외 처리한다.

* `peek()`
  스택의 맨 위에 있는 값을 확인한다.
  값을 확인만 하고 제거하지는 않는다.

* `print_stack()`
  현재 스택에 저장된 데이터를 `top`부터 순서대로 출력한다.

* `free_stack()`
  프로그램 종료 전 스택에 남아 있는 모든 노드를 해제한다.

---

### 실행 결과 및 정리

`push(1)`, `push(2)`, `push(3)`을 실행한 뒤 스택은 다음과 같이 출력되었다.

```text
top -> 3 -> 2 -> 1 -> NULL
```

이는 마지막에 삽입된 3이 스택의 가장 위에 있다는 뜻이다.

이후 `pop()`을 두 번 실행하자 3과 2가 순서대로 제거되었다.

```text
pop data = 3
pop data = 2
```

두 번의 `pop()` 이후 스택에는 1만 남았다.

```text
top -> 1 -> NULL
```

이후 남은 1을 제거한 뒤 빈 스택에서 다시 `pop()`을 실행하였다.
빈 스택에서 `pop()`을 호출했을 때는 다음과 같이 예외 처리 메시지가 출력되었다.

```text
[pop] stack is empty
```

이를 통해 스택이 LIFO 구조로 동작하며, 빈 스택에서의 예외 처리도 정상적으로 수행됨을 확인하였다.

## Challenge3. 이중 연결리스트 구현

### 실습 내용

단방향 연결리스트를 확장하여 이중 연결리스트를 구현하였다.
노드 5개를 추가한 뒤 정방향과 역방향으로 출력하였다.
이후 중간 노드인 30을 삭제하고 다시 정방향, 역방향 출력 결과를 확인하였다.

---

### 핵심 개념

이중 연결리스트는 각 노드가 다음 노드뿐만 아니라 이전 노드도 함께 가리키는 자료구조이다.
단방향 연결리스트의 노드는 `next` 포인터만 가지지만, 이중 연결리스트의 노드는 `prev`와 `next` 포인터를 모두 가진다.

따라서 이중 연결리스트는 앞에서 뒤로 이동할 수도 있고, 뒤에서 앞으로 이동할 수도 있다.

이중 연결리스트의 노드 구조는 다음과 같다.

```c
typedef struct Node {
    int data;
    struct Node *prev;
    struct Node *next;
} Node;
```

이번 실습에서 사용한 주요 함수의 기능은 다음과 같다.

* `append()`
  리스트의 마지막에 새 노드를 추가한다.
  기존 마지막 노드의 `next`가 새 노드를 가리키고, 새 노드의 `prev`가 기존 마지막 노드를 가리키도록 연결한다.

* `delete_node()`
  특정 값을 가진 노드를 삭제한다.
  삭제 대상 노드의 이전 노드와 다음 노드를 서로 다시 연결한 뒤, 삭제 대상 노드를 `free()`로 해제한다.

* `print_forward_simple()`
  첫 번째 노드부터 마지막 노드까지 정방향으로 출력한다.

* `print_backward_simple()`
  마지막 노드부터 첫 번째 노드까지 역방향으로 출력한다.

* `print_pointer_table()`
  각 노드의 이전 노드와 다음 노드 관계를 표 형태로 출력한다.

* `free_list()`
  프로그램 종료 전 모든 노드를 해제한다.

---

### 단방향 연결리스트와 이중 연결리스트 비교

단방향 연결리스트는 각 노드가 다음 노드의 주소만 저장한다.
따라서 구조가 단순하고 메모리 사용량이 적다.
하지만 이전 노드로 이동할 수 없기 때문에, 특정 노드를 삭제하려면 삭제 대상의 이전 노드를 따로 찾아야 한다.

반면 이중 연결리스트는 각 노드가 `prev`와 `next`를 모두 저장한다.
따라서 특정 노드에서 이전 노드와 다음 노드에 모두 접근할 수 있다.
삭제 연산에서는 삭제할 노드의 `prev`와 `next`를 이용해 앞뒤 노드를 바로 다시 연결할 수 있다.

삭제 연산을 기준으로 비교하면 다음과 같다.

* 단방향 연결리스트
  삭제할 노드의 이전 노드를 알아야 한다.
  이전 노드를 모르면 head부터 다시 탐색해야 한다.

* 이중 연결리스트
  삭제할 노드가 주어지면 `prev`와 `next`를 이용해 앞뒤 노드를 바로 연결할 수 있다.
  따라서 삭제 연산을 더 직관적으로 처리할 수 있다.

다만 이중 연결리스트는 각 노드마다 `prev` 포인터를 추가로 저장해야 하므로 메모리를 더 사용한다.
또한 삽입과 삭제 시 `prev`와 `next`를 모두 올바르게 수정해야 하므로 구현이 더 복잡하다.

---

### 실행 결과 및 정리

10, 20, 30, 40, 50 총 5개의 노드를 추가한 뒤 정방향으로 출력하였다.

```text
Forward order : 10 -> 20 -> 30 -> 40 -> 50 -> NULL
```

역방향 출력 결과는 다음과 같았다.

```text
Backward order: 50 -> 40 -> 30 -> 20 -> 10 -> NULL
```

포인터 연결 정보는 다음과 같이 출력되었다.

```text
DATA    PREV DATA       NEXT DATA
10      NULL            20
20      10              30
30      20              40
40      30              50
50      40              NULL
```

이후 중간 노드인 30을 삭제하였다.
삭제 후 정방향 출력 결과는 다음과 같았다.

```text
Forward order : 10 -> 20 -> 40 -> 50 -> NULL
```

삭제 후 역방향 출력 결과는 다음과 같았다.

```text
Backward order: 50 -> 40 -> 20 -> 10 -> NULL
```

삭제 후 포인터 연결 정보는 다음과 같이 변경되었다.

```text
DATA    PREV DATA       NEXT DATA
10      NULL            20
20      10              40
40      20              50
50      40              NULL
```

이를 통해 30이 삭제된 뒤 20의 다음 노드가 40이 되고, 40의 이전 노드가 20으로 변경된 것을 확인하였다.
즉, 이중 연결리스트에서 중간 노드를 삭제할 때 앞뒤 노드가 정상적으로 다시 연결됨을 확인하였다.
