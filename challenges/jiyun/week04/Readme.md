## Challenge1. 함수 작성 및 Caesar Cipher 구현

### 실습 내용  
함수를 직접 작성하고 호출하는 구조를 이해하기 위해  
Caesar Cipher 방식의 문자열 암호화 및 복호화 프로그램을 구현하였다.  

프로그램은 다음과 같은 함수로 구성하였다.  

- `print_banner()` : 프로그램 시작 배너 출력  
- `get_shift()` : 사용자로부터 shift 값 입력  
- `encode()` : 문자열을 shift만큼 이동시켜 암호화  
- `decode()` : 암호화된 문자열을 원래 상태로 복호화  

사용자로부터 문자열과 shift 값을 입력받고,  
encode 또는 decode 기능을 선택하여 결과를 출력하도록 구현하였다.

---

### 핵심 개념  

함수는 프로그램을 여러 기능 단위로 나누어 작성하기 위해 사용된다.  
이를 통해 코드의 가독성이 향상되고, 동일한 기능을 반복 작성하지 않아도 된다.  

또한 프로그램 수정이나 디버깅 시 특정 함수만 확인하면 되므로 유지보수가 용이하다.  

Caesar Cipher는 알파벳을 일정한 값만큼 이동시키는 암호 방식이며,  
알파벳 범위를 벗어나는 경우 다시 처음으로 돌아오도록 modulo 연산을 사용한다.

## Challenge2. gdb로 스택 프레임 관찰

### 실습 내용  

Challenge1에서 작성한 코드를 `gcc -g -O0` 옵션으로 컴파일한 후  
gdb를 이용하여 함수 호출 과정에서의 스택 프레임 변화를 관찰하였다.  

다음 항목을 중심으로 분석하였다.  

- rsp, rbp 값의 변화  
- call 명령어 실행 시 return address 저장  
- 함수 종료 시 스택 복원 과정 확인  

---

### 핵심 개념  

스택 프레임은 함수 호출 시 생성되는 메모리 공간으로,  
지역 변수, 이전 rbp 값, return address 등을 저장한다.  

- `rsp` : 현재 스택의 최상단을 가리키는 레지스터  
- `rbp` : 현재 함수의 기준이 되는 베이스 포인터  

함수 호출 시 call 명령어에 의해 return address가 스택에 저장되며,  
함수 종료 시 스택 프레임이 복원되고 원래 위치로 복귀한다.

---

### 실습 결과  

- call 명령어 실행 시 rsp 값이 8 감소하며,  
  스택 최상단에 return address가 저장되는 것을 확인하였다.  

- encode 함수 실행 중 rbp를 기준으로 스택 프레임이 형성되는 것을 확인하였다.  

- pop %rbp 실행 시 이전 rbp 값이 복구되고 rsp가 8 증가하였다.  

- ret 실행 시 스택에 저장된 return address가 rip로 이동하며  
  main 함수로 복귀하는 것을 확인하였다.  

---

### 원리  

함수 호출 과정은 다음과 같이 이루어진다.  

1. call 명령어 실행  
   → return address를 스택에 push  
   → rsp 감소  

2. 함수 실행  
   → rbp를 기준으로 스택 프레임 생성  

3. 함수 종료  
   → pop %rbp로 이전 rbp 복구  
   → rsp 증가  

4. ret 명령어 실행  
   → return address를 꺼내 rip에 저장  
   → 원래 함수로 복귀
