Challenge-3

단방향 대비 이중 연결 리스트의 장단점

장점
1. 특정 노드 삭제 연산 시 속도 (O(1))

단방향: 지워야 할 노드를 알고 있어도, 삭제해야하는 노드의 이전 노드를 찾기 위해 Head 부터 탐색 (O(N))
이중: 이전 노드와 다음 노드를 모두 알고 있으므로, 즉시 앞뒤를 이어 붙이고 특정 노드 삭제 가능 (O(1))


2. 양방향 순회(Bidirectional Traversal) 가능

단방향은 오직 앞으로만 갈 수 있지만, 이중 연결 리스트는 prev 포인터를 통해 역방향으로 탐색 가능
-> 웹 브라우저의 앞/뒤로 가기 또는 편집기의 Ctrl+Z/Y 같은 기능을 구현 시 사용

단점
1. 메모리 오버헤드 (Memory Overhead)

노드마다 prev 포인터를 저장할 공간이 추가로 필요 
-> 64비트 시스템 기준으로 노드당 8바이트의 메모리가 더 소모되기에, 다뤄야 하는 데이터가 많은 경우 메모리 낭비 발생 가능

2. 구현 및 유지보수 복잡도 증가

노드를 하나 추가하거나 지울 때 조작해야 하는 포인터의 수가 단방향(1개)에 비해 이중(2개 이상)으로 늘어나기에 메모리 누수나 UAF(Use After Free) 등의 보안 취약점이 발생할 수 있음
