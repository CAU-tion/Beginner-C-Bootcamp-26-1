#include <stdio.h>
#include <stdlib.h>

int main(){
        int *a = (int *)malloc(sizeof(int));
        *a = 10;
        free(a);
        printf("%d",*a);

        return 0;
}


free 전
0x5555555592a0: 10

free 후
0x5555555592a0: 1431655769

Dangling Pointer가 위험한 이유

논리적 오작동
프로그램이 메모리가 이미 해제되었다는 사실을 모른 채 Dangling Pointer를 통해 데이터를 계속 읽거나 수정하면, 오염된 값으로 인해 연산 오류, 예기치 않은 동작, 무한 루프 등의 버그가 발생할 수 있다.

Use After Free(UAF)

프로그램이 free(a)를 호출하면 힙 메모리 영역은 해제되지만, 포인터 a 자체는 여전히 이전 주소를 가리키고 있는 상태가 된다. 이 상태의 포인터를 Dangling Pointer라고 한다.

이후 프로그램이 새로운 malloc()을 호출하면, 메모리 할당자는 효율성을 위해 방금 해제된 힙 영역을 다시 재사용할 수 있다. 이 경우 새 포인터 b가 이전의 a와 동일한 주소를 할당받을 수도 있다.

공격자가 입력을 조작할 수 있는 상황이라면, b를 통해 해당 메모리 영역에 악의적인 데이터나 조작된 함수 포인터 값을 삽입할 수 있다.

프로그램이 Dangling Pointer인 a를 다시 사용하면, 이미 공격자가 변조한 데이터를 읽거나 실행하게 된다.

이 과정에서 함수 포인터, 객체의 vtable, 중요 변수 등이 조작되면 프로그램의 실행 흐름이 공격자 의도대로 변경될 수 있으며, 심한 경우 임의 코드 실행(Remote Code Execution)으로 이어질 수 있다.
