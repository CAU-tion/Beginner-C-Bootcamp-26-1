# Challenge1. 포인터 기초 실습
## 실행 결과 해석

### 포인터가 저장한 주소
```text
ptr이 저장한 주소 == num의 주소
```

포인터는 변수의 주소를 저장한다.

---

### 역참조 결과
```text
*ptr == num
```

포인터를 통해 실제 변수 값에 접근할 수 있다.

---

### 포인터로 원본 값 변경
```c
*ptr = 30;
```

원본 변수 `num` 값도 함께 변경된다.

---

## 포인터 크기 분석

```c
sizeof(ptr)
```

### 결과
- 64bit 환경 → 8byte
- 32bit 환경 → 4byte

### 이유
포인터는 데이터를 저장하는 것이 아니라 "메모리 주소"를 저장한다.

즉, 주소 체계 크기에 따라 포인터 크기가 결정된다.

---

# Challenge2. 포인터 연산 실습
## 1. 배열 이름은 시작 주소

```c
arr == &arr[0]
```

배열 이름은 첫 번째 원소의 주소처럼 동작한다.

## 2. 배열 접근과 포인터 접근

다음 두 표현은 동일하다.

```c
arr[i]
```

```c
*(arr + i)
```
즉, 배열은 내부적으로 포인터 연산 기반으로 동작한다.

# 포인터 증가 연산

## 코드

```c
ptr++;
```

## 실제 동작

`int*` 포인터라면:

```text
주소 + sizeof(int)
```

보통 4byte 증가한다.

---

## 주소 변화 예시

```text
0x1000
0x1004
0x1008
```

포인터는 자료형 크기만큼 이동한다.

---

## 배열 이름과 포인터가 동일하게 동작하는 이유
C언어에서 배열 이름이 배열의 첫번째 원소 주소로 자동 변환(decay)되기 때문이다.

# Challenge3. Call by Value vs Call by Reference

# Call by Value

## 개념
함수에 값을 복사해서 전달한다.

```c
swap_by_value(x, y);
```

함수 내부에서 값이 바뀌어도 원본 변수는 변경되지 않는다.

---

## 특징

### 장점
- 원본 데이터 보호
- 안정성 높음

### 단점
- 큰 데이터 복사 시 비효율적

---

# Call by Reference

## 개념
변수의 주소를 전달한다.

```c
swap_by_reference(&x, &y);
```

함수 내부에서 원본 메모리를 직접 수정한다.

---

## 특징

### 장점
- 원본 데이터 수정 가능
- 배열/구조체 전달 효율적

### 단점
- 원본 데이터가 변경될 수 있음

---

# Swap 함수 비교

## Call by Value

```c
void swap_by_value(int a, int b)
```

### 결과
```text
원본 값 변경 안됨
```

---

## Call by Reference

```c
void swap_by_reference(int* a, int* b)
```

### 결과
```text
원본 값 변경됨
```

---

# 결론

이번 실습을 통해 다음 내용을 확인할 수 있었다.

1. 포인터는 메모리 주소를 저장한다.
2. 역참조를 통해 실제 데이터에 접근할 수 있다.
3. 배열은 포인터 기반으로 동작한다.
4. 포인터 연산은 자료형 크기만큼 이동한다.
5. Call by Reference는 원본 값을 직접 수정할 수 있다.
